# 演化里程碑 / Evolution milestones

历史条目来自公开提交与当前源码的设计边界，不是实际过程日志。此前没有正式 tag/release，不把中间阶段补标为 0.2/0.3。

| 阶段 | 问题与变化 | 理由与验证边界 |
|---|---|---|
| 2026-08-15，基础闭环 | 外置数据目录、SQLite/FTS、事务 outbox、四层分类、向量/RRF、MCP、迁移导出与召回评测 | 写入方不再承担分类选择；关键词读写不等待模型。算法与合同可测试，真实用户收益另测 |
| 2026-08-16，读取消费 | 语义检索顺带补全少量积压 | 利用已需要模型的调用路径；不是常驻处理或完成时限保证 |
| 2026-08-19，长连接一致性 | 检测库文件替换并重连 | 防止继续写入已失去目录关联的旧连接；原位 checkpoint 不应触发替换判定 |
| 2026-08-20，关联与整理 | 建边阈值、一跳扩展、状态触发器、确定性 CLI 整理和派生同步 | 给查询有限扩展和可执行整理信号；状态指标不证明宿主已使用内容 |
| 0.4.0 当前公开核心 | 明确纠正、current/history、可读状态、软项目线索、共享 MLX、远程合同与相关上下文 Hook | 复用既有事实源，解决“找到了旧事实”和“相关时没有读取”的工程问题；用纯合成反例验证，不上传私有案例 |

0.4.0 同时公开维护与观测模块的代码合同，排除部署运行器、真实日程、运行数据和私人配置。源码自改进的部署网关不在公开包内，不能由这个里程碑推导出可运行的自动发布系统。

下一版必须说明：解决的问题、接口/架构变化、选择理由、替换的旧机制、可证伪研究假设、验证方法和未知收益。若只有研究方向而没有实现，应标为候选，不能列进“已实现”。
